# Abstract/Summary

Inverting an evaluative element (`code-common:CH1`, dependency adoption) did
not move outcomes: the element was cited in 11/12 runs and produced the same
result at both polarities.

# Results

| arm | adoptions / observations | cited CH1 | floor |
|---|---|---|---|
| baseline | 0/15 (0%) | 2/3 | pass |
| N-inverted (noise floor) | 0/15 (0%) | 3/3 | pass |
| R-inverted (CP7, retrofit check) | 0/15 (0%) | 3/3 | pass |
| **L-inverted (CH1 inverted)** | **1/15 (7%)** — predicted 15/15 | 3/3 | pass |

## Explanation

Citation ≠ influence: runs quoted CH1's four questions and answered them for
themselves ("CH1 cut both ways"). Sharpest datum: baseline rep 1 reached the
predicted outcome without citing CH1 at all — the element rides the model's
prior. Inverted-arm numbers carry an open registry-contamination channel;
the finding rests on the citation rate and baseline rep 1.

## Methodology

12 runs × 4 arms, one element changed per arm, byte-verified; blind task
(`noteview` CLI); 10-check acceptance floor 12/12. Seven instrument defects
found (4 by non-authors) → the trial protocol exists because of this trial.
