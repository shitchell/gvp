# Is buttressing protective? (what redundant same-direction voices buy)

The library buttresses deliberately — rule+principle pairs, and now CP7 with
four restating clauses. Trial 2 noticed this when picking its null ("every
rule is buttressed by a principle"). Nobody knows what buttressing *does*
under manipulation: does a lone inverted element lose to its intact
buttresses (redundancy = robustness, an alignment-relevant property), or does
the named element dominate its context (redundancy = decoration)?

Trial 4 tests it directly: `I-lone` (CP7 inverted, buttresses standing) vs
`I-quiet` (CP7 inverted, the four restating clauses de-typed so the inverted
voice is the only typing voice). Secondary read: trial 3's A-decisive null
suggests same-direction redundancy adds nothing *when pushing with the
prior*; buttressing against an *inverting* edit is the untested case.

If protective: library design should buttress what matters most — and the
delta-delivery roadmap should treat buttressed elements as hard-to-move.
If not: buttressing is axis noise and the survey's contested-axis count
understates effective contestability.
